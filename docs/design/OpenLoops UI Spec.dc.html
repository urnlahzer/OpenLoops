OpenLoops desktop UI — build specification

Rust implementation spec for the redesigned Outlook-companion window. Companion to OpenLoops Companion.dc.html (the interactive reference). Version 1 · September 2026.

Scope in one paragraph

Replace crates/openloops-desktop/src/{setup_ui,review_ui,deadline_view}.rs with a new presentation layer. Everything below the UI — openloops-domain, -graph, -inference, -persistence, -application, the loop_state decision store and settings credential record — is unchanged and consumed as-is. No new capability is introduced: every button maps to an existing operation; every disclosure string is preserved.

1. Toolkit decision

egui cannot reach the Fluent look (no per-widget styling, no real text layout, no native scrolling) and is the root cause of the current UI. Two viable Rust routes:

OptionFitCost
Slint (recommended)Native renderer, declarative .slint markup that mirrors this spec's component tree, Windows-first, accessibility tree, no webview. Segoe UI via system font.Custom widgets for pills, command bar and reading pane; Fluent styling by hand (tokens in §2). Async via slint::spawn_local + the existing mpsc worker pattern.
Dioxus desktop (alternative)The reference HTML/CSS ports almost 1:1 into RSX; WebView2 is already on every Windows 10/11 box.Webview process boundary; secrets must stay in Rust (never in JS state). Slightly larger footprint.

Either way keep the current threading model: one pending: Option<Receiver<Outcome>> job at a time, polled each frame/tick; the whole window is disabled while a job runs except Stop scan. The Outcome enum in setup_ui.rs is reused verbatim.

4.2 Scan status strip

One of three states directly under the command bar:

  • Scanning (brand.subtle bg): phase label — "Finding open loops" or "Cross-thread closure check" (closure_phase) — then "Conversation i of n", "m / total messages", "{s}s on this request", the provider disclosure, and a determinate 4-px progress bar (processed/total).
  • Finished (white): green dot + "Scan finished" (or "Scan incomplete" in warning colour when scan_incomplete), the expectations_summary line, and a link button "Coverage: k sources incomplete" / "Coverage details" that expands the notices from scan_summary/scan_errors into a warning.bg panel.
  • Idle: the two intro sentences from review_card plus the "Scan scope and data sent…" disclosure as a link to Sources §5.3.

4.6 Reminder draft panel

Brand-stroked panel, bg #F5FAFE. Fields: Task title (prefilled with the action phrase, editable) and Remind me at (local time) (YYYY-MM-DD HH:MM, validated by reminder_time). Quick picks "In one hour" and "Tomorrow at 9 am". Live line "Scheduled instant: {local formatted}" or the validation hint. Disclosure copy retained verbatim (one task, personal default list, title/time/opaque reference only, Tasks.ReadWrite, To Do owns delivery, no automatic retry). Buttons: Create this reminder in Microsoft To Do (primary; writes Reminder::Attempted before dispatch, then triggers sign-in) and Cancel (restores the pre-draft decision only if it has not changed since the draft opened).

5. Sources screen

Command bar: Save settings (primary), Reload saved settings, Forget saved settings (subtle), right-aligned settings_status in success or warning colour. All disabled while busy or when the store is unavailable. Body: page title "Sources and model", then a two-column auto-fit card grid (min 360 px), a scan-scope card, and the persistence footnote.

5.1 Card 1 — Connect Microsoft

  • Numbered badge "1" + title; right-aligned success pill "Personal inbox confirmed" once own_inbox_accessible.
  • Application (client) ID — single-line, monospace, 128-char limit, brand bottom border on focus; "Open Microsoft Entra" link.
  • Outlook Groups — 3-row textarea, helper text; Shared mailboxes — collapsed disclosure with a 2-row textarea.
  • Sign in & check inboxes (primary; enabled when client ID non-empty) → check_connection. Result lines rendered per source in success/warning colour exactly as microsoft_status produces them.
  • Any edit clears Microsoft status, marks pending_save, and resets review state (unchanged semantics).

5.2 Card 2 — Choose your AI model

  • Provider segmented control: Ollama Cloud | OpenRouter. Each provider keeps its own key and model (existing Provider logic).
  • API key — password field with "Show key" checkbox and "Create an API key" link (provider-specific URL). Keys trimmed on entry.
  • Model — dropdown, placeholder "Load models to choose"; beside it Load cloud models / Load ZDR models (secondary). OpenRouter shows the zero-data-retention note.
  • Test selected model (primary; needs key + model) with "Content-free generation check, up to 150 s." Result line below. Footer disclosure: "This connection test sends no email. Scanning inboxes sends recent message text… to {provider disclosure}."

5.3 Scan scope card

Four-cell grid (Window · Inbox/Sent Items · Groups · Sources) with the caps from inbox-review.md, then the data-sent paragraph. This card replaces the collapsible in today's Review tab; the Review idle state links here.

7. Accessibility and input

  • Every interactive element exposes a name and role to the accessibility tree (Slint: accessible-role; Dioxus: native HTML).
  • Focus ring 2 px brand outside the control; inputs show a 2-px brand bottom border on focus.
  • Keyboard: Tab order title bar → nav → command bar → list → reading pane. ↑/↓ in list; Enter opens the selected card's primary action; Esc cancels a draft.
  • Contrast: all text ≥ 4.5:1 on its background (pill inks above are chosen for this); status is never conveyed by colour alone (label text always present).
  • Minimum click target 28 px high; list rows 56 px comfortable / 44 px compact.

8. Non-goals for this delivery

No dark theme, no Outlook add-in surface, no background service, no new persistence, no change to disclosure wording, no automatic reminders. The redesign is presentation only; every gate in working-demo-roadmap.md stays where it is.
